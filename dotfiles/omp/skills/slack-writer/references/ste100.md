# ASD-STE100 for Slack explanations

ASD-STE100 (Simplified Technical English, "STE") is a controlled language from aerospace maintenance writing. It exists so that a tired reader, or a reader whose first language is not English, reads a sentence once and gets one meaning. That is the same problem a Slack explanation has: people skim it between other things, often during an incident.

Apply these rules to explanation text only (see "What counts as an explanation" in SKILL.md). Do not change code, commands, service names, file paths, URLs, log output, or quoted text.

## Words

- **One word, one meaning.** Pick one word for a thing and use it every time. If the first sentence says "cluster", do not switch to "database" or "DB" later.
- **Use the simple common word.** The list below covers the replacements that come up most in Slack. It is not the full STE dictionary; when a word is not here, pick the most common, concrete word that has one clear meaning.
- **Technical names and technical verbs are permitted.** `deploy`, `revert`, `restart`, `merge`, `rotate`, `configure`, `install`, `scale`, product names, and team jargon that the channel already uses are fine. They are the vocabulary of the domain, not decoration.
- **No phrasal verbs.** A verb plus a particle ("set up", "look into") often has more than one meaning. Use a single verb.
- **No "-ing" verb forms.** "We are examining" becomes "We examine". "After restarting" becomes "After you restart". Technical names keep their "-ing" ("load balancing", "logging").
- **No contractions.** "do not", "it is", "we will". This overrides the `_voice.md` rule for explanation text.
- **Keep the small words.** Keep "the", "a", "this", "these". Do not drop articles to make the sentence shorter; dropped articles are what make fragments hard to parse.
- **Noun clusters of three words or fewer.** "prod database cluster upgrade window" becomes "the upgrade window for the prod database cluster".

## Sentences

- **Length.** Procedural sentences (instructions): 20 words maximum. Descriptive sentences: 25 words maximum. The level in SKILL.md can make the cap shorter, never longer.
- **One instruction per sentence**, unless the two actions happen at the same time.
- **Instructions use the imperative.** "Run `aws sso login`." not "You will want to run `aws sso login`."
- **Active voice.** "The runner deleted the cache." not "The cache was deleted."
- **Verb forms:** simple present, simple past, simple future ("will"), imperative, and the past participle as an adjective ("the affected users"). No "would", "could", "might", "has been doing", "is going to".
- **Warnings and cautions go before the instruction they apply to**, and start with a clear command. "Do not delete the old key before you test the new one. Then delete the old key."

## Paragraphs

- One topic per paragraph. Put the topic sentence first.
- Six sentences or fewer per paragraph.
- Use a vertical list for steps or complex conditions. In Slack, steps use `1.`, `2.`, `3.` lines; other lists use `-`.

## Examples

**Cause line in an all-clear**

Before: `*Cause:* The runners were filling up on disk since we weren't pruning the docker layer cache, which kicked off a cascade of failed jobs.`

After: `*Cause:* The docker layer cache filled the disk on the runners. We did not prune the cache, so the jobs failed.`

**Steps for the reader**

Before: `You'll need to set up SSO before the 30th, so make sure you've installed CLI v2 and then go ahead and run configure sso.`

After:
```
Do these steps before November 30:
1. Install AWS CLI v2.
2. Run `aws configure sso`.
3. Make sure that `aws sts get-caller-identity` shows your SSO role.
```

**Reason for a decision**

Before: `We're moving off long-lived keys since they're a pretty big risk if they leak.`

After: `We will stop the use of long-lived access keys. If a key leaks, an attacker can use it until someone deletes it.`

## Self-check

Before you save, read each explanation sentence and check:

1. Is there a word with two meanings, or a word you switched for the same thing?
2. Is there a phrasal verb, an "-ing" verb, or a contraction?
3. Is the sentence over the word cap for its type and level?
4. Is there more than one instruction in it?
5. Is it passive?
6. Does a warning come after the instruction it protects?
